Strict reading of their llms.txt — you are mostly right

“…if your app displays data for a specific location, the attribution link must point to that location’s listing, not just the homepage”
The Model row: you’re right. The trigger in that sentence is data for a specific location. “Godzilla (Premium) — Stern, 2021” is catalog data — identical for every Godzilla Premium anywhere on earth, and it asserts nothing about APC. It does not trip the location-link clause.
The line beneath it: still does trip it. “Listed / Not listed” is a claim about APC’s lineup, and we only know it from their location payload. That is location-specific data by any reading, so that row needs the location link — in both states, which is why every mockup above links “Not listed” too. This is a different reason than I gave you last turn; I was wrong that the Model row was the trigger.
One residual on the catalog data. CC BY-SA 4.0 wants attribution for any use of the data, catalog included. Their own text says a generic pinballmap.com link “is fine for general credit (e.g. an about page)”. We link from the machine page today, so we’re covered either way — but if the Model row ever outlives the Pinball Map row on some surface, that surface needs a credit somewhere.
The logo: don’t. Their llms.txt says nothing about logos or brand assets, and we have no Pinball Map asset in the repo. More to the point, CC BY-SA licenses the data, not their marks — a logo is a trademark and we have no grant to use one as a UI label. I also can’t go look at their site to check (CORE-PBM-001 forbids crawling them). If you want it, it’s an email to them, not a design decision. A gets you the same “no repetition” outcome with no permission question.

Typing in a Model — the flow exists as a bead, not as code

PP-3bbr is exactly this: split model identity (title, manufacturer, year, opdb/ipdb) from the Pinball Map catalog match, with a “Use Pinball Map’s data” checkbox — checked means derived and read-only, unchecked means hand-entered and the machine isn’t listable. Today those fields are copied from the catalog on match and the schema comment says they are “never trusted from the client”, so there is no writable path at all. Two questions it leaves open: validation for client-supplied values, and what happens when a hand-entered model is later matched to a catalog title — do catalog values overwrite, or only fill blanks?

So “Not specified” is honest but currently a dead end — nothing in the UI can change it until PP-3bbr ships. Want me to pull it into this bead, or keep it separate and let the row read “Not specified” for now?
