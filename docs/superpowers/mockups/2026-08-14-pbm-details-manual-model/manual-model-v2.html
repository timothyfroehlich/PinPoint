Manual Model — against what the field actually does today

Current state I had wrong. The right-hand column is one always-present slot that is already three-way: the required Edition select for a multi-edition family, the Reason (optional) text input when the machine is marked Not on Pinball Map, and a disabled placeholder otherwise. It is deliberately never empty so the field doesn’t reflow. So there is no free column — in the exact state we’re designing for, Reason is already sitting in it.

Cost: unsortable and unfilterable — the admin fleet table (PP-o355.7) can’t group by manufacturer or decade, and the Info tab’s Model row would show a sentence where every other machine shows a title. Probably disqualifying, but worth naming since it is zero work.

Two things I need from you.

1. Is “Title” actually a field? PP-3bbr says hand-enter Title / Manufacturer / Year, but the machine already has a Name — and for a homebrew, Name is the title (“Bordertown”). A separate model Title would be the same string typed twice, and they’d drift. My mockups above drop Title and keep only Manufacturer + Year. Say if you want it back.

2. Precedence, still open from before. Someone hand-enters Bordertown / Homebrew / 2019; months later Pinball Map adds Bordertown and the machine gets matched. Does the catalog overwrite the typed values, fill only blanks, or prompt? Note the DB makes this sharper than I realised: NOT (pinballmap_machine_id IS NOT NULL AND pinballmap_excluded) — linked and excluded are mutually exclusive by CHECK constraint, so matching a hand-entered machine necessarily clears pinballmapExcluded, and with it the state the typed values live in.
